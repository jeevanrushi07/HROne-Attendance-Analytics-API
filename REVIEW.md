# REVIEW.md

The starter was reviewed against `openapi.yaml` and `DATA_MODEL.md`.

| # | Where | What is wrong | How to notice | Fix applied |
|---|---|---|---|---|
| 1 | `health()` | Returned success without contacting MongoDB. | Stop MongoDB and request `/health`. | Ping MongoDB and return 503 on failure. |
| 2 | `create_employee()` | Check-then-insert allows concurrent duplicate codes; `created_at` was a naive datetime. | Send concurrent requests with the same `emp_code`; inspect epoch output. | Unique index, catch duplicate-key error, store UTC BSON datetime and serialize as epoch milliseconds. |
| 3 | `EmployeeIn` | Missing contract-level patterns, lengths, date validation and shift inequality. | Submit malformed employee codes, emails, dates, or equal shift times. | Add Pydantic constraints and validation. |
| 4 | `list_employees()` | `skip` used `page * page_size`; `total` counted all employees. | Request page 1 and a department filter. | Use `(page - 1) * page_size`, filtered count, stable sort. |
| 5 | `compute_late_minutes()` | Naive datetimes and a shift start on the punch's calendar date break timezone/overnight logic; truncation and strict boundary need to be explicit. | Test 09:40:00, 09:40:01 and an overnight punch. | Convert instants to UTC/IST at boundaries, use record date, truncate to seconds and apply the strict 600-second threshold. |
| 6 | `compute_work_hours()` | Python `round()` uses banker's rounding and binary floats. | Test a duration whose hour value lands on a half-cent boundary. | Use Decimal with `ROUND_HALF_UP`. |
| 7 | `compute_overtime()` | Always uses the same calendar date and has no 30-minute threshold. | Test an overnight shift and 29/30 minutes after shift end. | Compute overnight end on the next day and apply the threshold. |
| 8 | `punch_in()` | Unknown employees cause a server error; timestamps used local naive time; duplicate prevention relied on a race-prone read before insert. | Punch for an unknown code; submit simultaneous identical punches. | Return 404, validate epoch milliseconds, compute IST attendance date and rely on a unique compound index. |
| 9 | `list_attendance()` | Loaded every match into Python, sorted in memory, and did not validate date range/status/pagination bounds. | Test 100k rows, invalid dates, and `date_from > date_to`. | Push filter, sort, count, skip and limit into MongoDB and validate inputs. |
| 10 | Missing `punch_out()` | Endpoint was absent. | Call the documented endpoint. | Implement an atomic update, time interval validation, work hours, overtime and half-day calculation. |
| 11 | Missing regularization endpoint | No audit trail or concurrency-safe correction logic. | Correct a record and inspect history; issue concurrent patches. | Recompute derived fields, record only actual changes, append history with compare-and-swap and return 409 on conflict. |
| 12 | Missing monthly analytics | No aggregation-based employee summary. | Request a month with and without attendance logs. | Aggregate stored derived values and calculate weekday working days from `joined_on`. |
| 13 | Missing department summary | No cross-collection summary; a logs-first design would omit employees with no logs. | Include an eligible employee with zero logs. | Start from employees and `$lookup` attendance logs, then aggregate at department level. |
| 14 | Missing late leaderboard | No competition ranking or tie-aware cutoff. | Tie at the `limit` boundary. | Use `$setWindowFields` with `$rank`, then filter rank. |
| 15 | Missing department trend | No gap filling or moving average. | Request a range with weekends and empty days. | Generate the calendar in MongoDB and calculate the seven-row moving average with `$setWindowFields`. |
| 16 | Missing explain endpoint and indexes | No execution plan endpoint or indexes for workload queries. | Inspect `executionStats` on seeded data. | Create idempotent indexes at startup and expose explain output. |
| 17 | Response serialization | Mongo datetimes/ObjectIds could leak or violate the epoch-millisecond contract. | Inspect create, attendance and history responses. | Convert timestamps to integer epoch milliseconds and omit internal `_id`. |

## Reviewed and retained

- The natural key for attendance is `(emp_code, date)`, not MongoDB `_id`; this matches the data model.
- Employee codes are supplied by the client and must not be generated by the API.
- Analytics read stored `late_minutes`, `overtime_minutes`, `work_hours` and `half_day` values rather than silently recalculating seeded records.
